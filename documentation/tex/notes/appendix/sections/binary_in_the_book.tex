Table \ref{tab.bitsInTheBook} lists each operation of this appendix against the code of the
book that uses it.
The first three rows are on the path of every session:
a write after every change of a size, a lookup on every pass of the matching loop,
and the walk to the reported depth after every message.
The last four compute the gap statistics of a side when they are asked for alone,
cutting the window with Proposition \ref{prop.rankByShift} and counting it.
Inside the fold of a session they are not used:
\codehl{side\_statistics} walks the reported levels anyway, since it returns them,
and reads each gap as the difference of two consecutive occupied prices less one.

\codehl{TickArrayBook} reaches the last four rows from three methods.
\codehl{span\_bits} cuts the window with \codehl{keep\_highest\_set\_bits},
which reaches the lowest set bit through \codehl{count\_trailing\_zeros}
when it shifts the window down to an odd integer;
\codehl{gap\_count} counts it with \codehl{count\_binary\_gaps};
and \codehl{largest\_gap\_size\_between\_non\_empty\_levels} measures its widest gap with
\codehl{measure\_largest\_binary\_gap},
which floods every gap by one bit a pass until the window is a solid block of ones,
so that the number of passes is the width of the widest gap.

The lowest set bit appears in no row on the path of a session, and that is by design.
Counting its asks down from the ceiling of the band,
Section \ref{sec.fasterBook},
makes the best price the highest set bit on both sides,
so no lookup pays the $O(\bandWidth)$ of Section \ref{sec.binaryCosts}.
The same reversal puts the levels beyond the reported depth at the low end of the integer on
both sides, so the window of the gap statistics is one cut for either.
